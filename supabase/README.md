# ربط داشبورد رويال فالي بـ Supabase

## 1. قاعدة البيانات والصور

أنشئ مشروع Supabase، ثم افتح SQL Editor والصق محتوى `supabase/setup.sql` كاملًا وشغّله.
ينشئ جدول البرامج، قائمة المديرين، وصلاحيات RLS، ومساحة `umrah-images` للصور.
يمكن إعادة تشغيل الملف؛ لا يحذف بيانات البرامج.

## 2. حساب الإدارة

من Authentication → Users → Add user أنشئ حسابًا ببريدك وكلمة مرور قوية، مع تأكيد البريد عند إنشاء الحساب بواسطة لوحة Supabase.
انسخ User UID للحساب ثم شغّل الأمر التالي في SQL Editor بعد استبدال القيمة:

```sql
insert into public.admin_users (user_id)
values ('ضع-هنا-User-UID'::uuid)
on conflict do nothing;
```

لا توجد صفحة تسجيل حسابات عامة في الموقع. المستخدم المسجل لا يحصل تلقائيًا على صلاحية إدارة.
لإلغاء صلاحية مدير، احذف عضويته من `admin_users` عبر لوحة Supabase؛ الحماية تطبق على الطلبات التالية حتى لو بقيت واجهته مفتوحة.

## 3. الربط بالمشروع

انسخ `.env.example` إلى `.env.local` وضع رابط مشروعك ومفتاح **Publishable** من نافذة Connect أو Settings → API Keys:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
```

لا تستخدم Secret أو service_role في هذه المتغيرات أو ترسلها في الشات. التطبيق يحتاج المفتاح العام فقط؛ RLS هي التي تحمي الكتابة والمسودات.
أعد تشغيل `npm run dev` ثم افتح `http://localhost:3000/admin/`.
في الاستضافة، اضبط المتغيرين في بيئة **البناء** وأعد البناء والنشر لأن Next.js يضمّن متغيرات NEXT_PUBLIC في ملفات المتصفح.

## 4. الاستخدام

- أضف صورة JPG/PNG/WebP حتى 5 ميجابايت، الاسم، المدة والتفاصيل.
- السعر بالجنيه المصري اختياري؛ تركه فارغًا يعرض «السعر عند الاستفسار».
- يمكنك إضافة تاريخ السفر وفندقي مكة والمدينة وترتيب العرض.
- احفظ كمسودة، أو فعّل «نشر البرنامج على الموقع».
- الموقع يجلب البرامج المنشورة عند فتح الصفحة أو تحديثها؛ لا تحتاج إعادة نشر الموقع لكل برنامج جديد.
- استخدم «إخفاء» لإيقاف عرض برنامج. الحذف النهائي غير متاح في النسخة المبدئية.

بدون متغيرات الربط، تعرض `/admin/` معاينة فارغة مع محرر وتجربة اختيار صورة محلية؛ لا تحفظ بيانات وهمية ولا تدّعي نجاح الحفظ.
الصور في bucket عام حتى لو البرنامج مسودة؛ استخدم صورًا تسويقية فقط. لا ترفع مستندات شخصية.
عند استبدال صورة يتم الاحتفاظ بالقديمة لتجنب كسر صفحات مخزنة مؤقتًا. يمكن تنظيف غير المستخدم يدويًا بعد التأكد من عدم استخدامه.

## 5. التحقق قبل الاستخدام الفعلي

1. سجل دخول المدير، أضف مسودة: تظهر في الإدارة ولا تظهر في نافذة زائر خاصة.
2. انشرها ثم حدّث صفحة الزائر: تظهر الصورة والتفاصيل. أخفها وتأكد من اختفائها بعد التحديث.
3. جرّب حسابًا ليس في `admin_users`: لا يفتح الإدارة ولا يستطيع إضافة/تعديل البرامج أو رفع الصور، حتى عبر API.
4. جرّب حفظ تعديل وتغيير صورة وترتيب برنامجين؛ تحقق من ظهور التغييرات بعد تحديث الموقع.
5. جرّب انقطاع الاتصال: يجب ظهور خطأ وعدم رسالة نجاح وهمية.

تم إعداد الكود للربط، لكن تنفيذ SQL واختبار الدخول والصلاحيات على مشروعك يتطلبان إعداد Supabase الفعلي.

المراجع: [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)، [مفاتيح API](https://supabase.com/docs/guides/getting-started/api-keys)، [صلاحيات Storage](https://supabase.com/docs/guides/storage/security/access-control).
